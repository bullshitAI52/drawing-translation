# 图纸翻译源码

DXF 图纸文本提取及基于 Excel 对照表的译文标注工具，使用 Python、Tkinter、pandas 与 ezdxf。

## 归档状态

本仓库保存上传者提供的原始源码，5 个 Python 文件保持原始内容。文件从提供的压缩包中提取；仓库未包含原 ZIP。本次仅整理文件与说明，未修复业务逻辑，未做图纸处理或图形界面运行验证。

## 源码中的功能

- 递归查找 `.dxf` 文件，提取模型空间和块中的文本并导出 Excel。
- 读取 Excel 前两列作为原文与译文映射，将译文添加到图纸中。
- 图形界面提供提取、翻译、位置偏移、颜色和文字高度选项。
- 包含本地机器码及注册逻辑，按原包保留。

这是基于现成对照表的标注流程，源码未接入在线翻译或 AI API。仅针对 DXF；函数中的 `dwg` 命名不代表支持直接读取 DWG。

## 文件结构

| 文件 | 用途 |
| --- | --- |
| `main.py` | Tkinter 图形界面 |
| `f.py` | 提取 DXF 文本并导出 Excel |
| `t.py` | 读取映射、添加译文并保存 DXF |
| `registration.py` | 本地注册状态与机器码逻辑 |
| `注册码生成.py` | 原包附带的注册码生成脚本 |
| `requirements.txt` | 根据导入及 Excel 读写整理的第三方依赖，未锁定版本 |

## 环境准备

需安装带 Tkinter 的 Python；建议在虚拟环境中安装依赖。以下为待调试的启动方式，不代表已通过运行验证。

```sh
python -m venv .venv
# 激活虚拟环境后执行：
python -m pip install -r requirements.txt
python main.py
```

Tkinter 属于 Python 的 GUI 组件，不通过此 requirements 文件安装。

## 已发现、尚未修复的问题

- `main.py` 期望 `t.process_directory()` 返回总计、成功和失败数量，但该函数当前没有返回值。
- `t.py` 的命令行入口调用 `process_directory()` 时参数数量与定义不一致。
- `f.py` 导出的前两列为文件路径和文本；`t.py` 需要的前两列则是原文和译文，因此提取结果不能未经整理直接作为翻译表。
- 未注册时的选项卡禁用范围包含注册页，注册入口逻辑需检查。
- TEXT 与 MTEXT 的属性处理、块内文字定位和线程中的界面操作尚待运行验证。
